# 候选参数检索与排名：流程现状

> 整理日期：2026-08-16。
>
> 文档角色：说明完整系统的入口、现有基础和待设计部分。本文是现状摘要，不代表排名规则已经冻结。

## 1. 当前结论

| 项目 | 状态 |
| --- | --- |
| 流程目标 | **已确认**：专家提供若干候选参数及理由，AI 检索和审查证据，形成可解释排名，再由人选择或授权系统选择 |
| 完整实现 | **尚未形成**：当前没有可直接运行的“多候选输入 -> 统一评估 -> 排名 -> 选择”完整模块 |
| 可复用基础 | 齐志杰已有参数无关的[两阶段研究 Agent](<../02_机制与文献证据/01_当前实现/deep_research_agent_v13/README.md>)，可作为逐参数文献检索和机制证据结构化组件；当前访问部分外部服务需要 VPN／网络代理 |
| 当前校准案例 | `SHRGT45` 是专家给定的首个真实案例，不是系统排名选出的第一名 |
| 当前搭建顺序 | 技术负责人可以先接入 SHRGT45 全流程，同时预留本入口；不必等待排名模块完成 |

## 2. 预期流程

```text
专家输入候选参数、原始理由和适用边界
  -> 逐参数核对定义、数据来源与可观测性
  -> 检索支持、反对和不确定证据
  -> 按统一维度评分并解释差异
  -> 输出候选排名、风险和待确认项
  -> 人工选择，或明确授权“由系统决定”
  -> 选中参数进入机制与文献证据流程
```

候选输入至少应保留：参数名称、专家原话、提出者／来源、输入时间与版本、物理理由、预期适用范围和待确认问题。具体数据结构由技术负责人设计。

每个候选的输出至少应包括：

- 参数定义、单位、观测层级和数据可得性；
- 专家理由中哪些有支持、哪些有反证、哪些仍是推测；
- 物理相关性、证据质量、可验证性、实现成本和主要风险的分项评价；
- 各项分数对应的证据、引用位置和不确定性；
- 淘汰／保留理由、推荐候选及需要专家确认的问题；
- 最终选择人、选择时间和采纳／否决理由。

## 3. 当前候选来源

[老师答疑二](../../01_项目定义与设计依据/04_专家意见与答疑/01_天文老师原文/老师答疑2.md)提出了可供系统测试的候选及理由：

- 剪切角占比与平均剪切角的组合；
- `MEANGBT`：强梯度区域与爆发相关；
- `MEANALP`：二维 twist／alpha 代理；
- `TOTUSJZ`：垂直电流与重联相关；
- `TOTPOT`：光球过剩磁能及能量注入相关。

这些内容是**专家候选池和初始理由**，不是已经确定的严格排名。老师明确表示难以仅凭经验给出可靠顺序，也不建议只因总磁通量容易预测耀斑就优先选择它；系统应同时考虑科学解释价值，而不是只追求预测性能。

## 4. 排名边界

1. 初始排名用于决定先验证哪个候选，不能代替真实数据验证或科学结论。
2. 不能把所有参数先跑完，再根据最好看的最终结果倒推排名和补写理由。
3. 文献影响力、来源质量和“该文献对当前主张的证据强度”必须分别记录。
4. 排名必须保留分项分数、权重、证据和冲突，不能只输出总分或序号。
5. 评分维度、权重和算法尚未锁定，由技术负责人提出方案；调整时必须记录版本和影响。
6. 人工选择是默认边界；只有用户明确选择“由系统决定”，系统才获得本次参数选择权。
