# SHRGT45 全信息基准版：最新 Demo 使用数据

> 对应权威版本：`SHRGT45_全信息基准版_20260808`  
> 整理日期：2026-08-14  
> 本包定位：只整理当前 Demo 实际使用的数据、规则、结果和 control 审计依据；不混入 0806 及更早版本，也不复制 FITS、图表、脚本或历史 ZIP。

## 先说清这份数据包是什么

这是一份面向复核和后续汇总的**数据包**，不是新的分析版本。它把 0808 Demo 中真正参与输入、门控、最终结果和 control 审计的数据按用途重新分层：拿到包后，可以从事件种子一路追到 55 条最终记录，也可以单独追查某条同 AR 时间 control 为什么被保留、排除或替换。

当前 Demo 使用 6 个事件种子建立查询，理论记录数为 360 条，JSOC 实际返回 333 条。最终结果只使用 `55 = 37 + 18` 条记录，覆盖 4 个事件和 4 个 AR。18 条 control 均为同 AR 时间对照；没有正式独立安静活动区 control。

## 数据从哪里流到哪里

1. `01_核心输入与规则/` 中的事件种子、查询清单和 6 份关键词 JSON 定义了主运行的输入；
2. `02_主运行记录/01_all_returned_records_with_final_status.csv` 保存 333 条实际返回记录及其门控、标签和最终状态；
3. 通过 AR 映射、历史窗和位置门后，按事件前 3--6 小时窗口形成 37 条正候选；
4. 临时 control 必须经过完整 NCEI M+ 区间审计。51 条中有 36 条排除、15 条保留，并以 3 条同 AR 替换记录补齐为 18 条最终时间对照；
5. `03_最终Demo结果/01_final_analysis_sample.csv` 是所有下游斜率、相关和结果图表的唯一权威样本表。

`04_control审计与替换依据/` 中的严格前推 JSON 和候选表只用于解释那 3 条替换记录的来历。它们不能与主运行的 333 条记录合并，更不能据此新增最终样本或宣称存在正式独立阴性组。

## 先看哪些文件

1. 看最终数据：`03_最终Demo结果/01_final_analysis_sample.csv`。
2. 看数字从哪里来：`02_主运行记录/02_gate_counts.csv` 和 `03_最终Demo结果/02_continuous_distribution.csv`。
3. 看某条 control 是否合格：`04_control审计与替换依据/01_final_control_audit.csv`、`02_final_control_replacements.csv` 与 NCEI 目录子集。
4. 看规则：`01_核心输入与规则/04_数据处理规则.md`、`05_DataPlan.md`。
5. 看某份文件是否属于本 Demo：`00_阅读说明/数据使用清单.csv`，其中列出来源、角色、行数和使用边界。

## 必须保留的使用边界

- 55 条记录来自 4 个 AR，三小时历史窗存在重叠；不能把行数解释为独立样本数。
- 同 AR 时间 control 通过的是未来 0--6 小时完整 M+ 区间筛查，不是正式独立阴性样本。
- 主运行事件输入的 provenance 仍需以审计表的 `NEEDS_CLARIFICATION` 状态为准。
- 本包没有 FITS；磁图拉取后仍需独立核验 `DATE-OBS`、`T_REC`、`HARPNUM`、WCS、`BUNIT`、shape、NaN 和坏像素。
- 本包共纳入 37 份从 0808 主包复制的输入、记录、结果和审计文件；未复制旧版本、脚本、图表或压缩归档。
