# 严格对照审计整合说明

本目录把 `SHRGT45_严格阴性对照前推检索_20260807` 的完整证据并入 `SHRGT45_全信息基准版_20260808`，用于补充主 Demo 对同 AR 前推时间候选的审查。

## 阅读顺序

1. `01_阅读说明/严格阴性对照前推检索结论.md`：先看本轮结论、6 个 AR 的结果和边界；
2. `02_审计数据/活动区最终选择摘要.csv`：查看每个 AR 是否找到代表时间点；
3. `02_审计数据/全量目录清洁候选门控.csv`：查看 672 个候选格点的目录门；
4. `02_审计数据/严格数据门汇总.csv`、`逐帧关键词核验.csv`：查看 strict 数据门和 16 帧证据；
5. `02_审计数据/AR11429候选更正审计.csv`：查看旧候选被排除的完整区间证据；
6. `03_复现与完整性/本轮复现说明.md`、`验收检查.csv` 和 `文件hash清单.csv`：核对复现和封存完整性；
7. `05_复现脚本/`：查看离线重建和封存脚本。

## 路径说明

审计 CSV 中的 `raw_json_relative_path` 是相对于严格审计根目录的路径，便于与复现记录逐项对应。在全信息基准版中，实际文件位于：

`03_结果数据/09_严格对照审计/02_审计数据/raw_jsoc_keywords/`

NCEI M+ 目录快照也已随包保留在 `02_审计数据/02_official_Mplus_event_catalog_NCEI_v1-0-1_subset.csv`，因此整合后的严格审计脚本不需要依赖工作区外部的目录文件。

`04_原始检索包/` 保留原始的 20260807 严格检索 ZIP 和发送包哈希清单；`06_整合后审计封存包/` 是按新目录路径重新生成的严格审计 ZIP。两者分开保存，避免把原始封存对象和整合后的副本混为一谈。

## 结果身份

3 个通过 strict 数据门的时间点是同 AR 时间候选，不是正式独立阴性 control；本整合目录不把它们并入主 Demo 的 37/51 记录统计，也不生成正式 TSS、HSS、AUC 或验证结论。

本轮没有查询 `CMASK`、有效像素数和有效像素比例，相关测量边界保留为 `NOT_AVAILABLE_IN_INPUT`。
