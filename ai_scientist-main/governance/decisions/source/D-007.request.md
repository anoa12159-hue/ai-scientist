# D-007 Replay 人工闸门位置与动作请求

> 状态：`REQUEST_FOR_REVIEW`
>
> 决策上下文：`PROJECT_GOVERNANCE`
>
> 闸门：`GOV_REPLAY_GATE_PLACEMENT`

## 1. 背景

`D-002=A` 已确认首个 MVP 使用两个 Replay 人工闸门，但尚未冻结它们在 LangGraph 中的精确位置和允许动作。`D-006=A` 又要求前端只消费后端聚合 `RunReadModel`，因此闸门状态必须由图和追加式 Ledger 产生，并通过 Read Model 展示。

现有契约有两个不可省略的条件：

1. `FIXTURE_IMPORT_REVIEW` 的请求必须绑定本次 Run 已生成的实际 `FindingRef`、相关 `ArtifactRef`，以及表示尚无上游 Artifact 的能力缺口所需的 `StageAttemptKey`；
2. `FINAL_REPLAY_REVIEW` 只能针对精确的、不可变的 Report ArtifactRef 产生内部演示 ReleaseDisposition，不能授权正式统计、公开发布或比赛发布。

## 2. 共同图约束

```text
S01 -> S02 -> S03 -> S04
S04 -> S05
S04 -> S06
S05 + S06 -> S07
```

S05 和 S06 必须并列。任一必需分支失败时，可以生成内部诊断 Run Summary，但不能进入可供 `FINAL_REPLAY_REVIEW` 的最终 ReportManifest。

## 3. 选项

### A（推荐）：S01–S06 完成后、S07 之前；S07 完成后、内部演示之前

```text
S01 -> S02 -> S03 -> S04 -> (S05 || S06)
                         -> FIXTURE_IMPORT_REVIEW
                         -> S07 ReportRenderer
                         -> FINAL_REPLAY_REVIEW
                         -> READY_FOR_INTERNAL_DEMO（最多）
```

#### Gate 1：`FIXTURE_IMPORT_REVIEW`

位置：所有 S01–S06 Replay Adapter/确定性校验完成，且两条并列分支都已产生其可用的 Artifact、ValidationReport 和 Finding 后，S07 `ReportRenderer` 之前。

进入闸门时：

- Graph State 只保存本次尝试的 Run/Stage/Artifact/Finding/Validation/Lineage 引用；
- 生成绑定实际哈希的 `DecisionRequest`，展示 171 文件 Fixture 导入审计、0808/0814 包边界、兼容性问题、Gap、失败和缺口；
- `APPROVE_FOR_REPLAY` 只对请求上下文中列出的精确 Finding/Artifact 生效，并派生 `ACCEPTED_FOR_REPLAY`；
- `REJECT` 或未处理的必需错误停止 S07，不生成最终 ReportManifest；需要修正时必须创建新导入尝试/新 Artifact，禁止原地改 Fixture 或 Finding；
- 未知路径、哈希、Schema、来源、配置或授权错误始终 Fail Closed，不允许用本闸门“接受”。

#### Gate 2：`FINAL_REPLAY_REVIEW`

位置：S07 已生成不可变的系统原生 `ResearchSummary/ReportManifest`，且 S05/S06 Join 条件满足之后；内部演示发布之前。

进入闸门时：

- 请求绑定精确的 `Report ArtifactRef`、Run/Workflow 版本、所有必需 Finding 的当前 Disposition 和 `join_policy`；
- `APPROVE_INTERNAL_DEMO` 只派生内部开发演示的 `ReleaseDisposition`，报告仍保持 `scientific_verdict=NOT_EVALUATED`、`authorization_status=NOT_AUTHORIZED`、`result_maturity=DEVELOPMENTAL`；
- `REJECT` 或 Join 不满足时，不产生可演示 Release；报告内容变化后必须创建新的 Report Artifact 和新的审核请求；
- 本闸门不能产生 `PUBLIC_OR_COMPETITION_RELEASE`，后者必须由独立 `expert_reviewer` 对同一精确报告另行授权。

优点：第一闸门拥有所有 S01–S06 实际接缝证据，满足 FindingRef/ArtifactRef 绑定要求；第二闸门只审阅已经完整生成的不可变报告；任何人工动作都不能修改历史字节或伪造科学结论。

### B：S01 之前导入闸门；S07 之后最终闸门

先扫描和校验所有 Fixture，人工批准后才启动 S01；S07 完成后再进行 `FINAL_REPLAY_REVIEW`。

优点是尽早阻止坏 Fixture 进入图。代价是第一闸门通常没有 S02–S06 适配器生成的实际 Finding/Artifact，难以满足现有契约的精确绑定要求；后续阶段才发现的版本接缝只能另造隐含闸门或绕过审批，因此不推荐作为首个 MVP 的唯一 `FIXTURE_IMPORT_REVIEW`。

### C：S04 后、S05/S06 之前；S07 之后最终闸门

在数据与统计验证完成后先人工审核，再放行反例审查和磁图 QA 两个并列分支。

优点是能在主数据导入后尽早暂停。代价是 S05/S06 自身的导入缺口、QA Finding 和报告输入尚未进入第一闸门，第一闸门的“完整 Fixture/兼容性审查”语义不完整；需要额外的分支失败路由，复杂度高于 A。

## 4. 推荐选择

推荐 `A`。它同时满足“两个闸门”“S05/S06 并列”“实际 Finding/Artifact 精确绑定”“最终报告不可变”和“内部演示不等于正式发布”五项约束。第一闸门虽然位于 S07 之前，但审查的是完整的 S01–S06 导入与适配结果，而不是把目录白名单审批误当成运行时 Finding 接受。
